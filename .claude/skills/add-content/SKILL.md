# 学習コンテンツを追加・変更する

`src/content/` はこのアプリの中核資産です。ここが壊れると学習体験が成立しません。

## 0. 必ず読むもの

1. `docs/content-decisions.md` — **会話文の方針の最終権威**
2. `docs/content-spec.md` — データの契約と検証ルール
3. `docs/会話文集.md` — 全58文の原稿(v0.2)。実データの正
4. `src/content/types.ts` — 型
5. `src/content/CLAUDE.md`

## 1. 追加する内容を確認する

- どの章か(第1章「家の中」/ 第2章「一日の暮らし」/ 第3章「外に出る」/ 第4章「学びと世界」)
- 新出漢字は何か(**1文につき最大1字**)。第2段階専用の特別回なら新出漢字なし
- 既存データの `order` のどこに入るか

**学習順序に割り込む場合は特に慎重に。** 順番を1つ変えると、第2段階の対象字が
未習になり、「読みが変わった」演出が空振りする可能性があります。
未習漢字そのものは許容されているので、壊れるのは第2段階の配置だけです。

## 2. 書く

### 未習漢字は使ってよい

**既習漢字だけで縛らないでください。** ふりがな＋英訳があるので読めます。
既習だけで書くと不自然な文しか作れず、「日本語に触れている」実感が失われます。
対象50字の外の字(星・旅・今)も、あとで習う字を先に出すことも許容されています。

未習を避けるのは **第2段階の演出をする漢字の周辺** と **推測クイズの出題** だけです。

ただし「なるべく使わない」方針は変わりません。とくに**第1章は無料範囲で離脱が
最も起きる場所**なので、未習が多すぎて新出漢字が埋もれていないか気をつけてください。

### 守ること

- **1文につき新出漢字は最大1字**
- **第2段階の対象字は、その回より前に導入済みであること**(最重要)
- 第2段階が2字同時の場合は `kanjiIds` に両方入れる(時間=時+間、大学=大+学、外国=外+国)
- 例外字(天・本・語)は音読みで導入し、第2段階の対象にしない
- 会話は1〜2往復。登場人数は2人の回と3人の回を混ぜる
- 各キャラの口調を守る
  - **空(猫)は単語だけ。挨拶と応答をしない**。空が出る回はミアとのやりとりを1往復以上
  - **ミアは空に対してだけタメ口**。対おばあちゃんは丁寧語
- 経過時間に依存する内容(「もう秋ですね」等)を書かない
- **ふりがなは `segments` に分けて書く。** ひらがな全文の文字列ではない
  ```ts
  japanese: 'たくさん歩きましたね。',
  segments: [{ text: 'たくさん' }, { text: '歩', reading: 'ある' }, { text: 'きましたね。' }],
  ```
  漢字を含むセグメントには必ず `reading` を付け、連結が `japanese` と一致させる。
  新出漢字は単独のセグメントに分ける(ハイライトがセグメント単位のため)。
  詳細は `docs/content-spec.md` の「行データの形」
- 英訳・ローマ字(ヘボン式)を全行に付ける
- 第1章の文は `isFree: true`、それ以外は `false`

## 3. 機械検証

```bash
pnpm run validate:content
```

落ちたら直します。**検証ルールを緩めて通すことは絶対にしないでください。**

## 4. 監査

`content-auditor` サブエージェントを呼びます。渡すもの:

- 追加・変更した内容
- 「キャラの口調・語彙レベル・会話の自然さを見ること」

指摘を反映します。

## 5. 開発者の最終確認を仰ぐ

**AIは日本語コンテンツの承認者ではありません。**
要件定義書 5.4 の通り、日本語ネイティブである開発者本人の検品が必須です。

追加した会話文を**そのまま読める形で提示**し、確認を求めてください。
「検証を通しました」だけで完了にしないこと。
