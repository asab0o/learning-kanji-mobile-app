# 作業録を追記する

`docs/log/README.md` の取り決めに従って、`docs/log/YYYY-MM.md` に1エントリ追記します。

## 1. 前回のログ以降を集める

まず今月のログファイル(`docs/log/<今月>.md`)を読み、**最後のエントリの日付と
関連コミット**を確認します。ファイルが無ければ新規作成します
(先頭に種別ヘッダと `# 作業録 YYYY-MM` を置く)。

そのうえで、前回以降の差分を集めます。

```
git log --format='%h %ad %s%n    %(trailers:key=Co-authored-by,valueonly)' --date=short <前回の最終コミット>..HEAD
git status --short
```

未コミットの作業も対象です。コミット済みかどうかではなく、
**作業がひと段落したかどうか**が区切りです。

## 2. 下書きを作る

集めた差分に加えて、この期間に追加・更新された `docs/decisions/ADR-*.md` と
`docs/plans/*.md` を読みます。**やり直しや方針転換の理由はたいていそこに書いてあります。**

`docs/log/README.md` のエントリ形式で下書きを作ります。埋め方の原則は3つ。

- **`Co-Authored-By` trailer があるコミット = AIが書いた。無ければ人が手で書いた。**
  ここは git から機械的に読めるので、勝手に上書きしない
- **「AIに任せたこと」は自分の作業を書く。** このセッションで自分が何をしたかは分かるはず
- **「人がやったこと」は推測で埋めない。** ADR やプランに明示的に書かれていること以外は
  `<!-- TODO: 要確認 -->` を置いて空ける。ここを埋めるのは開発者の仕事です

「やり直した / 詰まったこと」は、**この期間に捨てた案・戻した変更・
うまくいかなかったやり方**を探して書きます。書くことが無ければ省いてよい。

## 3. 確認を取ってから書く

下書きを**チャットに提示して**、開発者に確認してもらいます。特に見てほしい点を明示します。

- 主導(🤖 / 👤 / 🤝)の判定が合っているか
- `<!-- TODO: 要確認 -->` を今埋められるか

承認を得てから `docs/log/<今月>.md` の**末尾に追記**します。

## やってはいけないこと

- **過去のエントリを書き換えること。** 追記のみ。訂正も新しいエントリで行う
- **「人がやったこと」を想像で埋めること。** 空欄のほうが害が少ない
- コミットを1つずつエントリにすること。区切りは作業のかたまり
- コミットメッセージを日本語に訳し直して並べただけのログにすること。
  それは `git log` で読める。**ログに書くのは git に残らないもの**
