# 実装プランを作る

## 1. 要求を確認する

引数(`$ARGUMENTS`)が機能名です。空なら何を計画するか聞いてください。

先に `docs/plans/` を見て、**同じ機能のプランが既にないか確認**します。
あれば新規作成せず、それを更新する提案をしてください。

## 2. architect サブエージェントを呼ぶ

`architect` を **run_in_background: false** で呼びます(結果を待つ必要があるため)。

渡すプロンプトには必ず以下を含めてください。

- 機能名と、開発者が言った要求そのまま
- 「`docs/plans/README.md` のテンプレートに従ってプランを返すこと」
- 既存の関連プランがあればそのパス
- 開発者が付けた制約(あれば)

## 3. プランをファイルに書く

architect が返したプランを `docs/plans/<kebab-case-の機能名>.md` に保存します。
ステータスは `提案中` にしてください。

このとき**内容を勝手に膨らませない**でください。architect の設計判断を尊重し、
明らかな誤り(実在しないファイルパス等)だけ直します。

## 4. 承認を得る

プランの要点を開発者に提示します。全文を貼らず、以下だけを見せてください。

- 目的(1〜2文)
- スコープ外
- 変更ファイル数と主なもの
- 受け入れ条件
- リスク・未確定事項

そして **ExitPlanMode で承認を求めます。**

## 5. 承認後

`docs/plans/<機能名>.md` のステータスを `承認済み` に更新します。

そのまま実装に入ってよいか確認し、進める場合は `/implement docs/plans/<機能名>.md` の
手順に従ってください。

## やってはいけないこと

- 承認前にプラン以外のファイルを書くこと
- architect を呼ばずに自分でプランを書くこと(設計とレビューの分離が崩れます)
- 受け入れ条件が検証不能な書き方(「正しく動く」等)のまま承認を求めること
