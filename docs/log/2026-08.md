**やり直した / 詰まったこと**

  `feat/romaji-converter` を切ったが、`furigana.tsx` を読んで
  「画面はセグメント配列を要求しているのに、データは平坦な文字列」と分かり、
  コミット前に `feat/line-segments` に改名して作業内容ごと差し替えた。
  **残った知見: プランを書く前に、その機能が実際に使う既存コードを読む。**
  今回は実データ0行の時点で気づけたが、58文書いたあとなら145行の書き直しだった
- **マイグレーションを2回作った。** 1回目は `ADD COLUMN ... NOT NULL` に既定値がなく、
  行がある表に当てられない形だった(実測: 空なら通る、行があると
  `Cannot add a NOT NULL column with default value NULL`)。
  `drizzle-kit drop` で取り消そうとしたら `.sql` とスナップショットだけ消して
  `_journal.json` と `migrations.js` の巻き戻しに失敗し、中途半端に壊れた。
  生成物は追跡下なので `git checkout --` で戻した。
  **残った知見: `drizzle-kit drop` は信用せず、生成物は git で戻す**
- **既定値を付けたら型が緩んだ。** `'[]'` を付けた結果、drizzle の `$inferInsert` が
  `segments` を optional 扱いにし、シードの入れ忘れを型で防げなくなった。
  レビューの指摘で戻り型を `& { segments: string }` に締めて解決。
  **既定値はマイグレーションの都合、型は実装の都合で、別々に締められる**
- **プランの検証手順に穴があった。** 実装ステップ13が「アプリを削除してから入れ直す」
  だけだったが、削除すると空の DB に連続適用されるだけで、
  既定値を付けた理由(行がある表への `ADD COLUMN`)を一度も通らない。
  レビューが指摘。実機では**削除前に行を注入してからアップグレード**し、
  注入した行が `segments = '[]'` で生き残ることを確認した。
  **残った知見: 「安全側に倒した変更」の検証は、危険側の状態を作ってから当てる**
- **説明の根拠を1つ間違えた。** `focus` をデータに持たない理由を
  「SRS の復習カードで別の字を光らせたいから」と書いたが、要件定義書 5章は
  「SRS復習の出題は意味の選択式クイズのみ」で、会話文を再表示しない。
  正しい根拠は 4.6 の「ステップ1では新出漢字、第2段階では読みが変わる字」。
  プランの記述も差し替えた。**判断自体は正しかったが、理由が実装と合っていなかった**
- **受け入れ条件が厳しすぎた。** 「`rg "furigana"` が 0 件」という条件が、
