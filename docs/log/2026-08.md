## 2026-08-28 ローマ字変換器を作った(レビュー3周)

- 主導: 🤝 協働
- 関連: plans/romaji-converter.md / 未コミット

**やり直した / 詰まったこと**

- **レビューを3周して、毎回「静かに間違う」欠陥が出た。** 1周目4件・2周目4件・3周目3件。
  共通していたのは**テストは通り `pnpm run check` も通るのに、実データで壊れる**こと。
  - 全角句読点(`、` `。` `…`)が Script=Common なので、
    `\p{Script=Hiragana|Katakana|Han}` という**否定形の検知網から漏れていた**
  - `……` を1文字ずつ置換して6点になっていた。ドットは許可リストを通るので印も立たない
  - 読みの末尾の促音が消える、読み付きセグメントが連続すると語が割れる、など
  **残った知見: 検知網は「弾くものを並べる」ではなく「許すものを並べる」形で書く。**
  否定形で書くと必ず Script=Common の穴が空く
- **修正が次の欠陥を生むパターンが2回起きた。** 「行末か句読点の前でだけ助詞を剥がす」
  ガードを足したら `を` が行中で剥がれなくなり、それを直したら撥音の直後で剥がれなくなった。
  **`を` は現代語で助詞用法しかないので、他の助詞と同じ扱いにしてはいけなかった**
- **レビューが実データを流したことで、道具の位置づけが変わった。**
  第1章26行を実測すると、綴りは全行正しいのに**20行で語境界の手直しが要る**と分かった。
  「下書きを直して貼る」ではなく「**綴りの辞書引き**」だった。
  手順書が「確認印が付いた行を直す」と書いていて、印の無い行は素通りしてよいと読めたので、
  「全行を目で見る」に書き換えた。**印の設計より、印が何を見ていないかの明示のほうが効いた**
- **プランの表に自己矛盾があった。** architect の原案が「b の前の撥音は `m`」と決めながら
  例外表で `こんばんは` → `konbanwa` としていた。`kombanwa` に直した
- `drizzle-kit` と違い今回は依存を1つも増やさずに済んだ。形態素解析を入れない判断は、
  分かち書きを人がやる前提にしたことで成立している

**未回収の借り**

- **マクロン(`ō` `ū`)とアポストロフィの実機描画は未確認。** ローマ字表示 UI が未実装のため。
  会話文画面を作る回に、Hiragino Mincho ProN のラテン文字フォールバックで欠けないか見る
