# 作業録の書き方

`log/YYYY-MM.md` に月ごとに追記していく。目的は2つ。

1. **git に残らない判断と回り道を残す。** 何を作ったかはコミットを見れば分かる。
   分からないのは「なぜその順で作ったか」「何を捨てたか」「どこで詰まったか」
2. **人がやったこと と AIに任せたこと を分けて残す。** リリース後に振り返るとき、
   自分が何を判断したのかが分からなくなるのを防ぐ

## 絶対に守ること

- **追記のみ。過去のエントリを書き換えない。** 間違いに気づいたら、新しいエントリで訂正する
- **「人がやったこと」を推測で埋めない。** ここは本人しか知らない。
  分からなければ `<!-- TODO: 要確認 -->` を置いて空けておく

## AI と人の切り分け

**機械的な層は git が持っている。** コミットの `Co-Authored-By` trailer が
あれば AI が書いたもの、無ければ人が手で書いたもの。ログ側で二重に書かない。

**ログに書くのは git から復元できない層。** どの案を選んだか、何をやめたか、
どこで方針転換したか。

## エントリの形

区切りはコミット単位ではなく**作業のかたまり**。1回の作業で複数コミットしたなら1エントリにまとめる。

```markdown
## 2026-08-16 桜テーマのトークン層を立ち上げた

- 主導: 🤝 協働
- 関連: ADR-0004 / plans/theme-sakura.md / `858d37c`..`32d5825`

**人がやったこと**

- デザイン16案から「春 ／ 春泥棒」を選定
- 背景画像を生成AIで作り、プロンプトを確定

**AIに任せたこと**

- theme トークン層と ThemeProvider の実装
- ふりがなレンダリング

**やり直した / 詰まったこと**

- 背景をベクター合成で組む方針を捨て、画像1枚に変更(`15f4ba3` → `32d5825`)
```

`主導` は3値。

| 印 | 意味 |
|---|---|
| 🤖 | AI主導。人は要求を出して結果を確認しただけ |
| 👤 | 人主導。AIを使っていないか、補助的にしか使っていない |
| 🤝 | 協働。判断は人、実装はAIなど分担がある |

**「やり直した / 詰まったこと」が一番価値がある欄。** 書くことが無ければ省いてよいが、
迷った記憶があるなら必ず残す。

## いつ書くか

作業がひと段落したとき、`/log` で書く。フックで自動追記はしない。
自動生成すると「人がやったこと」が埋まらないまま量だけ増えるため。
