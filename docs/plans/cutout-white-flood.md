# プラン: cutout-white-flood

作成日: 2026-09-04
ステータス: 完了
要件定義書の対応箇所: なし(開発ツールの不具合修正。元プランは `illustration-cutout.md`)

## 目的

輪郭線の内側にある白 —— 塗られていない山、白いシャツ、日の白いハイライト —— が
切り抜きで消えないようにする。イラストを引き直さなくても、描かれたとおりの絵が
アセットになる状態にする。

## 背景

`rembg`(顕著性セグメンテーション)は「白い領域＝背景」と判定する。
2026-09-04 に実測した値:

| 生画像 | 場所 | RGB | alpha |
|---|---|---|---|
| `mountain-v2.png` | 真ん中の白い山 | 255,255,255 | **0**(alpha matting を切っても 15) |
| `mountain-v2.png` | 左の緑の山 | 213,231,201 | 255 |
| `day.png` | 日の白い上部 | 253,254,255 | 255 |
| `day.png` | 空の淡いにじみ | 238,237,248 | **0** |

**「日の上部が抜ける」は誤診だった。** 日の白は残っており、抜けていたのは背後の空の
にじみ。これは輪郭線が無く端が白へフェードするため、どの方式でも境界が決まらない。
切り抜きでは直せないので生画像側の条件として文書化する(スコープ外)。

## スコープ外

- **`day.png` の引き直し。** 輪郭線の無いにじみは切り抜きで救えない。プロンプト側の
  条件を `docs/画風プロンプト定義.md` に足すところまでがこのブランチ
- 線の太さ・彩度のばらつき(元プランどおりスコープ外)
- 残り48字の生成

## 実装ステップ

1. `keying.py`: 外周と地続きの白だけを背景にするマスクを作る
2. 白判定のしきい値を外周から測って画像ごとに決める
3. `cutout.py` を差し替え、依存から rembg を外す
4. 既存2字を焼き直し、3テーマ背景に載せて目視で確認する
5. ドキュメントを直す

## 受け入れ条件

- [x] `mountain` の真ん中の白い山が、暗いテーマ背景の上で白く見える
- [x] `walk` の白いシャツ・靴が暗いテーマ背景の上で欠けない
- [x] 外周の白は抜ける(暗いテーマ背景の上で白い矩形が出ない)
- [x] 紙の明るさが 242 の生画像(`yama.png`)でも背景が残らない
- [x] 輪郭線の途切れから紙が流れ込んでも、被写体の中に穴が残らない
- [x] 同じ生画像を2回通すと出力バイト列が一致する
- [x] `pytest scripts/illustration-cutout` が通る

## テスト方針

`keying.py` は純粋関数なので合成画像でユニットテストする。守る性質は
「輪郭線の内側の白が残る」「外周の白が抜ける」「淡い色面の中の白い粒が埋まる」
「孤立した紙粒が捨てられる」「画像端に接した被写体が削れない」「紙の明るさに追従する」
「線の途切れからの流れ込みを埋め戻し、大きな抜けは埋めない」。
絵としての善し悪しは3テーマ背景に載せた目視で判断する。

## リスク・未確定事項

- **しきい値と `CLOSE_RADIUS` はトレードオフ。** 半径を上げると淡い色面の穴は埋まるが、
  腕と胴の隙間のような細い背景まで埋まって白く残る。残り48字を通す中で崩れたら
  `keying.py` の定数を動かす(`README.md`「効きが悪いとき」)
- **背景が残る側の失敗は自動検知していない。** 抜きすぎ(`MIN_SUBJECT_RATIO`)だけ警告が出る

## 実装後の記録

- **しきい値を固定値にできなかった。** 生画像の紙の明るさは中央値で 242〜255 と幅があり、
  固定 236 だと明るい紙の絵で淡い色面が斑に抜け、固定 250 だと暗い紙の `yama.png` で
  背景が丸ごと残る。外周の帯から測って `紙の代表値 - 5` にした
- **`closing` は縁で被写体を削る。** scipy の `binary_closing` は画像外を背景として
  収縮するため、画像端に接した地面が痩せた。元のマスクと OR して戻している
- **輪郭線の途切れという第3の失敗モードがレビューで出た。** `mountain` の地面右端は線が
  切れていて、そこから紙が流れ込んだ 19×17px の穴が焼き込まれていた(`yama` の雲に2つ、
  `day` に1つ)。`CLOSE_RADIUS` を上げる案は細い背景まで埋めるので不可。
  **画像のどの端にも接していない**背景だけを面積で判定して埋め戻す `fill_leaks` を足した。
  端に通じている背景(腕と胴の隙間)はどれだけ細くても触らないので、この線引きなら安全
- rembg・onnxruntime が依存から消え、170MB のモデルダウンロードも不要になった。
  1枚あたり数十msで終わる
