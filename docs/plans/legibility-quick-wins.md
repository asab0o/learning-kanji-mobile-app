## 設計の決めどころ

### 1. `textMuted` は全体の値を1つ変える(用途別のトークンを増やさない)

- α `.75` で `#FBF4F4` 上 **4.9:1**。`.70` だと 4.3:1 で届かない
- `textMuted` は文字以外にも使われている。ふりがな(`furigana.tsx:106`、学習中でない字)、漢字の樹の線とつぼみ(`kanji-tree-view.tsx:94,146`、`tree-grid-view.tsx:154`)がそれ。**これらも濃くなる。** ふりがなは読めるべき文字なので濃くなって正しい。樹の線だけは見た目で確かめ、重すぎたら別トークンに分けることを検討する(このブランチでは分けない。分けるならテーマ3種の方針とあわせて決める)
- 見出し系で使っている `theme.text` + `opacity: 0.78` は 5.3:1 あり、今回は触らない

### 2. コントラストをテストで守る

テーマは今後3種に増える予定(要件 5.3)。値を目で決めると同じ問題が再発するので、`themes.test.ts` に「`text` / `textMuted` が `background` 上で 4.5:1 以上」を足して全テーマに掛ける。

**限界:** 実際の地は `background` ではなく背景画像(`backdrop`、不透明度1)と `surfaceVeil` のカード。テストは `background` での近似で、画像の上での見え方はシミュレータで確かめる。テストのコメントにこの限界を書く。

### 3. 英訳は 14pt、会話のローマ字は 13pt

- 英訳は「読ませる文」なので、フィードバックの 14pt に合わせる
- ローマ字(トグル ON のときだけ出る)は補助なので一段下の 13pt にし、英訳との上下関係を残す
- 吹き出しの最大幅 236pt はそのまま。英訳が折り返しやすくなるので、一番小さい画面で確かめる

### 4. 正誤の1行

4択の直下、種明かし(クイズ)/ 読み(復習)の直上に置く。目線は選んだ選択肢のあたりにあるため。色は選択肢の枠と同じ `positive` / `negative`。**色はあくまで補強で、文字だけで意味が通る**ようにする。

| 画面 | 正解 | 不正解 |
|---|---|---|
| クイズ | `You got it!` | `Not quite.` |
| 復習 | `Correct` | `Not quite. You'll see it again soon.` |

- クイズはご褒美であって成績ではない(要件 4.4)ので、責める言葉を使わない。不正解でもすぐ下の種明かしが主役になる
- 復習の不正解は同じセッションの末尾でもう一度出る(`session.ts` の出し直し)ので、「また出る」は事実として言える
- 共通コンポーネントは作らない。2画面は `Choice` もそれぞれ持っている(「同じ見た目にそろえる」のコメントあり)ので、それに倣う

## テスト方針

- **`contrast.ts` にユニットテストを書く**(純粋関数)。白地に黒 = 21:1、同色 = 1:1、`rgba` の α を地に合成する計算が既知の値になること
- `themes.test.ts` で全テーマに 4.5:1 を掛ける
- 表示の変更(文字サイズ・正誤の行)はシミュレータで手動確認する。2画面の描画テストはこれまでも書いていないので足さない

## リスク・未確定事項

- **背景画像の上での実コントラストは測れない。** テストは `background` での近似。花びらや空のグラデーションの濃いところで読みにくければ、α をさらに上げる
- **樹の線が濃くなる。** 文字のためのトークンを線にも使っていたことの副作用。重すぎたら、樹専用のトークンに分けるかを判断する(分けるならテーマ3種の方針ごと)
- **ADR-0004(デザイン案の値)を変えることになる。** デザインの意図(散りぎわ・低彩度)は色相を変えないので保たれるが、「淡さ」は一段失われる。可読性を優先した判断として ADR-0010 に残す

## 実装後の記録

**プランから変えたこと**

- **正誤の1行を 17pt → 19pt の太字(`fontWeight: '600'`)にした。** reviewer の指摘。`positive` / `negative` は地の上で 3.62 / 4.00:1 しかなく、17pt の標準の太さでは本文の基準(4.5:1)に届かない。このブランチ自身が ADR-0010 で「読ませる文字は 4.5:1」と決めたのと矛盾するので、19pt の太字にして WCAG の「大きい文字」(基準 3:1)に入れた。トークンを濃くする案は、選択肢の枠の色も変わるテーマ全体の判断になるので採らなかった
- **`contrast.ts` で範囲外の α を弾くようにした**(reviewer の指摘。テストも追加)

**機械的な確認**

- `textMuted` が `.52` のままだと `themes.test.ts` が 2.73 で落ちることを確かめてから `.75` にした(4.87:1。`surfaceVeil` のカード上では 5.04:1)
- `pnpm run check` が通った
- reviewer の判定は合格。受け入れ条件の機械的な6項目をすべて満たす。`contrast.ts` の式は独立実装との照合で一致

**シミュレータ(iPhone 17e、390pt 幅、Release ビルド)で確認したもの**

- 会話画面: 英訳 14pt が吹き出しの幅(236pt)で自然に折り返して収まる。ふりがなは、通常の字(灰色)と学習中の字(accent)が区別できる
- クイズ: 問いかけが漢字の下にはっきり見える。不正解で `Not quite.`、正解で `You got it!`(19pt 太字)が4択の下に出て、その下に種明かしが続く
- 復習: 不正解で `Not quite. You'll see it again soon.`、正解で `Correct`。不正解の字は `Try again` 付きでセッションの後ろにもう一度出た(既存の挙動が壊れていない)
- オンボーディング・Today・課金画面の灰色の文字が、背景画像の青い部分でも読める
- 復習データは、シミュレータの DB で `lesson_events.completed_at` を1日前にずらして作った

**未確認・判断待ち**

- **iPhone 17 Pro では見ていない。** 幅が広い端末は折り返しが減る方向なので、17e で収まれば足りると判断した
- **漢字の樹の幹(字の下の太い灰色の棒)が以前より濃く見える。** 未習の枝(灰色)は色付きの枝より弱いままで、階層は保たれている。重いかどうかは開発者の判断待ち
- **会話のローマ字(13pt)と英訳(14pt)は、1pt 差では主従がほとんど見分けられない。** どちらも読めるので実害は無いが、差を付けるなら色かサイズでもう一段離す

**スコープに足したもの(開発者が承認)**

- **課金画面の法務リンクの区切り `·` を消し、リンクの間隔を 10 → 20 にした**(`paywall-view.tsx`)。`·` は罫線用の `theme.border`(α 0.2)で描かれていて、ほぼ見えていなかった。濃くする案もあったが、この行は `flexWrap` で折り返す前提なので、折り返すと行末・行頭に点だけが残る。点をやめて間隔で区切ることにした。20 は各リンクの `hitSlop`(10)の和で、これより狭めると当たり判定が重なる。iPhone 17e で3本が1行に収まり、区切りが見分けられることを確認した

**途中で気づいたこと(スコープ外)**

- シミュレータで Romaji の `Switch` がタップに反応せず、つまみのドラッグでしか切り替わらなかった。シミュレータの入力の癖かもしれない。トグルを作り直す作業(フィードバック#6)で実機で確かめる
