# コンテンツ仕様

`src/content/` に置く会話文・漢字データの契約。
このアプリの中核資産であり、ここが壊れると学習体験そのものが成立しない。

**方針の根拠は `docs/content-decisions.md`**(会話文 決定事項一覧)。
この仕様はそれをデータの契約に落としたもの。両者が食い違ったら決定事項が正。

型定義は `src/content/types.ts`、検証ルールは `src/content/validate.ts`。

## 規模

| 章     | テーマ       | 総文数 | 新出字 | 第2段階の回 | 課金     |
| ------ | ------------ | ------ | ------ | ----------- | -------- |
| 第1章  | 家の中       | 10     | 10     | 0           | **無料** |
| 第2章  | 一日の暮らし | 15     | 14     | 1           | 有料     |
| 第3章  | 外に出る     | 16     | 13     | 3           | 有料     |
| 第4章  | 学びと世界   | 17     | 13     | 4           | 有料     |
| **計** |              | **58** | **50** | **8**       |          |

実データは `docs/会話文集.md`(v0.2)。

## 未習漢字は使ってよい

**これが最も誤解されやすい点。** 決定事項 4章の通り、会話文には未習漢字を出してよい。

> ふりがな＋英訳があるため読める。既習だけで縛ると不自然な文しか書けなくなる

「読めない字があっても文の意味は取れる」という体験そのものが、漢字への恐怖を下げる
というアプリの目的に効いている。実際 `docs/会話文集.md` では 星・旅・今 などが
自由に使われ、対象50字のうち 花・川・本・新 は導入前の回にも登場する。

**したがって未習漢字は検証しない。** 代わりに `pnpm run validate:content` が
密度を章別に集計して出す。

```
未習漢字の密度(許容されているが、なるべく少ないほうがよい)
  第1章 家の中(無料)    8/10 文  延べ 21 字  1文あたり 2.1
  ...
  あとで習う字を先に使用: 花(#23→#36) 川(#31→#33)
```

第1章を明示しているのは、**無料範囲であり離脱が最も起きる場所**だから。
ここで未習が多すぎると「読めない字だらけ」に見え、新出1字がその中に埋もれる。
数値に合否はつけない。目視で判断する材料として毎回出す。

未習を使わないのは次の2箇所だけ。

1. **第2段階の演出をする漢字の周辺** — 「読みが変わった」ことに集中させたいため
2. **推測クイズの出題** — 既習漢字から推測させるのが目的なので定義上ゆずれない

## error になるもの(差別化機能が壊れる)

| ルール                                  | 内容                                                                                                                         |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `checkReencounterKanjiTaught`           | **最重要。** 第2段階の対象字が、その回より前に導入済みであること。訓読みを知らない字の読みが変わっても学習者には何も起きない |
| `checkReadingIntroduction`              | 訓読みを先、音読みを後。例外字(天・本・語)は音読みのみを登録し、第2段階の対象にできない                                      |
| `checkNewKanjiPerSentence`              | 1文につき新出漢字は最大1字。`newKanjiId: null` が許されるのは `reencounters` を持つ特別回だけ                                |
| `checkFreeChapterBoundary`              | `isFree` は第1章の文だけ `true`。課金境界と章の切れ目を一致させる                                                            |
| `checkChapterComposition`               | 章ごとの総文数・新出字数・第2段階回数が上表と一致(58文そろうまでは警告)                                                      |
| `checkSoraSpeechRule`                   | 空(猫)が挨拶・応答をしない。判定は語単位の完全一致(「はいる」を「はい」と誤判定しない)                                       |
| `checkLineFields`                       | ふりがな・英訳の欠落。ローマ字は生成方法が未確定のため検証しない                                                             |
| `checkWordReferences`                   | 漢字の樹の参照整合性                                                                                                         |
| `checkUniqueIds` / `checkOrderSequence` | ID重複と order の連番                                                                                                        |

## warning になるもの(演出の質)

| ルール                            | 内容                                                                                                        |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `checkReencounterProximity`       | 第2段階の対象字の初出が同じ章内。実データでは8回中4回が該当し、第4章は構造上避けられないため error にしない |
| `checkReencounterLineCleanliness` | 第2段階の演出行に未習漢字が混ざっている。実データでも #30 が該当                                            |
| `checkCompoundPartnerTaught`      | 熟語のもう一方の字が未習(決定事項では「望ましい」)。対象50字の外の字(曜など)は対象外                        |
| `checkSoraInteraction`            | 空が登場する回にミアとのやりとりが無い(空が受け身のオチ要員になっている)                                    |

## 第2段階のデータ構造

第2段階は **1つの語で複数字の読みが同時に変わる**ことがある(時間 = 時＋間 /
大学 = 大＋学 / 外国 = 外＋国)。8回中3回がこれにあたるため、`kanjiIds` は配列。

```ts
reencounters: [{ word: '時間', stage: 2, kanjiIds: ['k-toki', 'k-aida'] }];
```

「とき＋あいだ → じかん」という**語の組み立てが見える**ことが体験の核なので、
片方だけを記録すると「時 は じ になった」という報告に劣化する。

## 機械では検証できないもの → `content-auditor` の担当

- 語彙レベルが N5 初級者に対して難しすぎないか
- キャラの口調(ミア=対おばあちゃんは丁寧語 / **対空はタメ口** / 空=単語だけ)
- 会話が自然な日本語として成立しているか
- 1文が1〜2往復に収まっているか、登場人数が2人と3人で混ざっているか
- 経過時間に依存する内容(「もう秋ですね」等)が入っていないか

最終的な日本語の品質判断は**日本語ネイティブである開発者本人が行う**。
`content-auditor` はその前段の粗探しであり、承認者ではない。

## 追加のしかた

`/add-content` スキルを使う。

1. 対象の章と、追加する漢字/会話文を決める
2. `src/content/` のデータを編集
3. `pnpm run validate:content` で機械チェック
4. `content-auditor` サブエージェントで品質チェック
5. **開発者本人が日本語として最終確認**
