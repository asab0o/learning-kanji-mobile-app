# ADR-0002: 未習漢字を許容し、検証は第2段階の演出に絞る

日付: 2026-08-15
ステータス: 採用
置き換え対象: ADR-0001 で作った `checkNoUnlearnedKanji`(error)

## 背景

ハーネス構築時、`docs/requirements.md` だけを読んで
「会話文に未習漢字を混入させない」を最重要の検証ルールとして実装した
(`checkNoUnlearnedKanji`、error)。

しかし会話文集 v0.2 の作成過程では、その逆が既に決まっていた。

> **未習漢字の使用: 出してよい。** ふりがな＋英訳があるため読める。
> 既習だけで縛ると不自然な文しか書けなくなる
> (`docs/content-decisions.md` 4章)

この決定は会話ログの中にしか無く、リポジトリのどこにも書かれていなかった。
結果として、**完成済みの58文をデータ化すればほぼ全文が検証に落ちる**状態になっていた。

## 決定

1. `checkNoUnlearnedKanji` を**削除**する。未習漢字は検証しない
2. 代わりに `collectUnlearnedKanjiUsage` で**章別に密度を集計**し、
   `pnpm run validate:content` の出力に毎回出す。合否はつけない
3. error として残すのは **`checkReencounterKanjiTaught`**
   (第2段階の対象字が、その回より前に導入済みであること)
4. 決定事項一覧を `docs/content-decisions.md` としてリポジトリに取り込む

## 理由

- **未習漢字はアプリの目的に沿っている。** 「読めない字があっても文の意味は取れる」
  という体験そのものが、漢字への恐怖を下げるという目的に直接効く。
  既習だけで書いた文は「教材のための文」に見え、日本語に触れている実感を損なう
- **本当に守るべきなのは第2段階だけ。** 「読みが変わった!」という驚きは
  訓読みを知っていることが前提であり、未習の字の読みが変わっても学習者には何も起きない。
  ここが崩れるとアプリ最大の差別化がそのまま空振りする
- **密度は数値で見せる。** 「なるべく使わない」方針は変わっていない。
  ただし58文中ほぼ全文で警告が出るとノイズにしかならないので、
  ルールではなく集計にする。特に第1章は無料範囲で離脱が最も起きるため章別に出す
- **決定をリポジトリに置く。** 会話ログにしか無い決定は、次のセッションで必ず再発する。
  今回の食い違いの根本原因はこれ

## 同時に直したこと

| 項目                  | 内容                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Reencounter` 型      | `kanjiId: string` → `kanjiIds: string[]`。第2段階は8回中3回が2字同時(時間・大学・外国)で、旧型では表現できなかった                                                                         |
| 例外字                | `readingIntroduction: 'kun-first' \| 'on-only'` を追加。天・本・語は訓読みがほぼ使われないため音読みで導入する                                                                             |
| 空の禁止語            | 部分一致をやめ語単位の完全一致に。「はいる」が「はい」に誤反応していた。空の語彙領域は動作・位置なので設定通りの発話が弾かれていた。決定事項が名指ししていた「おかえり」「ただいま」も追加 |
| `checkReadingVariety` | 削除。決定事項に無い独自の閾値(40%)で、実際の設計(50字中11字=22%)では初回から必ず鳴った                                                                                                    |
| romaji の警告         | 削除。ローマ字生成方法が未確定(決定事項 8章の残作業)のため全文で鳴る                                                                                                                       |
| `content-auditor`     | ミアの「対空だけタメ口」を追記。旧ルールのままだと**正しい原稿を丁寧語に書き直させ**、短く易しい文という狙いを潰していた                                                                   |

## 却下した選択肢

- **未習漢字を1文あたりのしきい値で警告する**: しきい値の根拠が無く、
  会話文集では意図的に未習を使っているため大量に鳴る。集計のほうが判断材料になる
- **「あとで習う字」(花・川・本・新)だけ警告する**: これらは会話文集のメモで
  「未習のまま自然に使う」と明示された意図的な選択。学習者から見ると
  「前に読めなかった字が今日習う字だった」という再会になり、伏線として機能する
- **第2段階の回全体で未習を禁止する**: 実データの #17・#30・#38 が
  字・読・書 などで落ちる。演出行に絞った警告に留めた

## 結果として受け入れるトレードオフ

- 機械が止めてくれる範囲は確実に狭くなる。守りが薄い分は `content-auditor` と
  開発者本人の検品が担う(決定事項でも日本語の最終判断は本人と定めている)
- 第1章の未習密度は数値で出るだけで、合否判定はしない。目視の判断に委ねる
- 「同じ章内で第2段階を出さない」は実データが8回中4回破っているため警告に留めた。
  ルールを緩めるかどうかは保留(`docs/content-decisions.md` 5章に記載)
