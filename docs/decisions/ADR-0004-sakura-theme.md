# ADR-0004: 桜テーマの中身をデザイン案「春泥棒」で確定する

日付: 2026-08-16
ステータス: 採用

## 背景

要件定義書 5.3 はテーマ3種(ノーマル / 桜 / 東京の夜景)を定めているが、
中身は「桜 = 淡いピンク＋白」という一行だけで、具体的なカラーコードは
「デザイン依頼中」のまま残っていた(要件定義書 10章のチェックリスト)。

一方 CLAUDE.md 絶対規則1 は「色をハードコードしない、すべてトークン経由」と定めている。
トークンは**画面を書き始める前に**存在していないと意味がないが、`src/theme/` は空だった。
色が決まらないという理由でトークン層を先送りすると、後から全画面の色指定を洗い直すことになる。

デザイン依頼の成果として、Claude Design プロジェクト『日本らしいテーマの比較設計』に
16案(四季4案＋その他12案)が上がった。

## 決定

**16案のうち「春 ／ 春泥棒」の配色・書体・装飾ロジックを、桜テーマの中身として採用する。**
他の15案は保留とし、テーマIDと表示名は要件定義書に合わせて `sakura` / `Sakura` とする。

ノーマルと東京の夜景は今回定義しない。`ThemeId` にも入れない。

付随して以下を決めた。

- **日本語の明朝体は iOS 内蔵の Hiragino Mincho ProN を使う**(デザイン指定は Shippori Mincho)
- **背景装飾は画像生成AIで作った1枚を敷く**。プロンプトは `docs/テーマ背景プロンプト定義.md`
- **`kunBranch` / `onBranch`(漢字の樹の音訓の色)はデザイン案に無いため独自に決めた**

## 理由

### 1. 「春泥棒」は満開ではなく散りぎわを描いている

一般的な桜テーマは満開のピンクになりがちで、**学習画面の地としては彩度が高すぎる**。
この案は「花びらではなく落下の軌跡を描く」「桜テーマより彩度を一段落とす」という
方針を持っており、accent が `#D2839C` と鈍い。長時間読む画面の地として成立する。

要件定義書 5.3 が懸念していた「背景に絵が入ると上に載る文字の視認性が落ちる」問題に、
デザイン側から先に答えている案でもある。

### 2. テーマIDを `harudoro` ではなく `sakura` にした

「春泥棒」はデザイン案の名前であって、要件上の枠ではない。
要件定義書・アーキテクチャ・設定画面が一貫して「桜」で通っているところに
案の名前を持ち込むと、**同じものを指す語が2つになる**。案の出自はこのADRにだけ残す。

### 3. Shippori Mincho を同梱しない

デザイン指定の Shippori Mincho は Google Fonts で、iOS には入っていない。同梱すると:

- `package.json` に依存が増える(または TTF をリポジトリに置く)
- アプリサイズが 1〜2MB 増える
- `expo-font` の読込完了までスプラッシュを保持する処理が要る

一方 Hiragino Mincho ProN は iOS 標準の日本語明朝で、上記のコストがすべてゼロ。
見た目は Shippori Mincho よりやや硬いが、**日本語学習アプリとしてはむしろ
iOS ネイティブの字面に寄るほうが自然**。差し替えは `sakura.ts` の
`type.mincho` / `type.minchoBold` の2行で済むので、後から覆せる。

MVP を 2026/9/30 に出しきることが最優先である以上、見た目の完全一致より
「依存を増やさない」を採った。

### 4. 背景装飾を SVG ではなく生成画像にした

`react-native-svg` は既に依存にあり、デザインの装飾(グラデーション＋斜めのヘアライン＋
楕円の花びら)はコードでも描ける。しかし**紙の粒状感が出せない**。
画風プロンプト定義が漢字イラストに「粒状テクスチャ」を求めているのに、
背景だけツルッとしたベクターだと画面の中でちぐはぐになる。

生成画像1枚なら要件5.3 のアセット枠(テーマにつき1〜2枚)に収まる。

### 5. `kunBranch` / `onBranch` を独自に決めた

デザイン案は会話画面のモックだけで、漢字の樹の音訓の色を含んでいない。
しかし architecture.md はこの2色を**全テーマ必須のトークン**として要求している。
訓読み＝緑系 `#7E9A6B`、音読み＝青系 `#7F9BBA` を、桜の低彩度に合わせて置いた。
音読み側は装飾の春空 `#C5D6E8` を一段濃くした色で、テーマの中で浮かない。

いずれも枝の線とラベル用で、本文サイズの文字色には使わない
(地 `#FBF4F4` に対するコントラスト比が約3で、本文には足りないため)。

## 却下した選択肢

- **四季4テーマ(春夏秋冬)をまとめて実装する**: 要件は3枠しか持っていない。
  枠を4に増やすとテーマ切替UI・アセット枚数・確認工数がすべて増え、9/30に効いてくる
- **3テーマ分の配色を今すべて決める**: ノーマルと夜景のデザイン案はまだ選べていない。
  推測で埋めると、後で差し替えたときにトークンの意味がずれる
- **トークン層を後回しにして画面から作る**: 絶対規則1に正面から反する
- **`theme.color.background` のようにネストしたトークン**: CLAUDE.md と architecture.md が
  `theme.background` の形を明記している。ドキュメントとコードを食い違わせない

## 結果として受け入れるトレードオフ

**アプリが当面「桜」1テーマでしか動かない。**

テーマ切替UIも作っていない。設定画面にテーマ項目を出すのは、
2つ目のテーマが決まってからになる。

`ThemeId` が `'sakura'` の単一ユニオンなので、テーマを増やすときに
`Record<ThemeId, Theme>` が型エラーになる。これは意図的で、
「IDを足したのに定義を書き忘れる」を型で止めるための形。

**暫定のプレビュー画面が本番エントリに載っている。**
`src/app/index.tsx` の唯一のルートが `src/features/reading/theme-preview.tsx` で、
これはテーマの見た目を実機で確認するためだけのモック。
**削除トリガーは本物の会話画面(reading)の実装**で、そのときファイルごと捨てる。
会話文は『会話文集.md』32番の原稿どおりだが、この文字列は `src/content/` の外にあるため
`pnpm run validate:content` の検査対象外である点に注意。

また、Hiragino Mincho ProN は iOS 専用のフォント名なので、
`react-native-web` でプレビューすると別の書体にフォールバックする。
本アプリは iOS のみ(絶対規則12)なので実害はないが、Web で見た目を確認しても
書体の判断材料にはならない。
