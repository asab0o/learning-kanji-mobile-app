# ADR-0010: 補助の文字色 `textMuted` を、読める濃さまで上げる

日付: 2026-09-23
ステータス: 採用

## 背景

1.0.0(ビルド5)を触った人から「グレーの文字が背景に対して薄い」「会話画面の英訳が小さすぎる」と
指摘を受けた。英訳は `textMuted` で描いているので、2つの指摘は同じ文字に重なっている。

桜テーマの `textMuted` は、デザイン案「春泥棒」(ADR-0004)の値 `rgba(69,59,65,.52)` を
そのまま採っていた。これを地の `background`(`#FBF4F4`)に合成して測ると、コントラスト比は
**2.7:1**。WCAG AA の本文の基準(4.5:1)にも、大きい文字の基準(3:1)にも届いていなかった。

`textMuted` は「本文より一段弱い文字」のトークンだが、実際には**訳文・かなの読み・ふりがな**など、
学習者が読まなければならない文字に使っている。飾りの文字ではない。

## 決定

**`textMuted` の α を `.52` から `.75` に上げる。** 色相(`69,59,65`)は変えない。
地の上のコントラスト比は **4.9:1** になる。

あわせて、**全テーマの `text` と `textMuted` が `background` の上で 4.5:1 以上あること**を
`src/theme/themes.test.ts` で検査する。

## 理由

- 読ませる文字に使っている以上、補助の色でも本文と同じ基準を満たす必要がある
- α `.70` だと 4.3:1 で届かず、`.75` が基準を満たす最小に近い値。デザインの淡さを必要以上に削らない
- 色相を変えないので、デザイン案の意図(散りぎわ・彩度を一段落とした配色)は保たれる。
  失われるのは「淡さ」の一段だけ
- テーマは今後3種に増える予定(要件定義書 5.3)。**目で値を決めると同じことが再発する**ので、
  基準をテストに置く

## 却下した選択肢

- **用途別にトークンを分ける**(読ませる文字用の `textSecondary` を足し、`textMuted` は淡いまま残す):
  今回の指摘はほぼ全部が「読ませる文字」で、淡いままで困らない使い道が見当たらない。
  トークンを増やすと、テーマを足すたびに決める値が増える
- **英訳の文字サイズだけを上げる**: 色が 2.7:1 のままでは、大きくしても大きい文字の基準(3:1)にも届かない

## 結果として受け入れるトレードオフ

- **`textMuted` を文字以外にも使っている箇所が濃くなる。** 漢字の樹の枝の線とつぼみ
  (`kanji-tree-view.tsx` / `tree-grid-view.tsx`)がそれ。重く見えるなら、樹専用のトークンに
  分けるかをテーマ3種の方針とあわせて判断する
- **テストが測れるのは近似。** 実際の地は `background` の上に敷いた背景画像と `surfaceVeil` のカードで、
  画像の色は場所によって違う。画像の上での見え方はシミュレータで確かめる
