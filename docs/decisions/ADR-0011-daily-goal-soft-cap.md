# ADR-0011: 1日3字を「上限」から「目標」に変え、第2段階を翌日以降に回す

日付: 2026-09-23
ステータス: 採用(ADR-0003 を置き換える)

## 背景

1.0.0 を触った人から「初日の3字を終えると、その日やることが無くなる」と指摘を受けた。
インストール直後は意欲が一番高いのに、そこで行き止まりになる。

ADR-0003 は上限3字の理由を3つ挙げていた。見直すと、どれもこの MVP では弱い。

1. **1字あたりが重い** — 1日の**既定**の量としては今も正しい。ただ、進みたい人を止める理由にはならない
2. **復習の雪崩を防ぐ** — 1字につき未消化の復習は常に1件なので、キューは学習済みの字数、
   つまり最大50件で頭打ちになる。全問正解で回すと、ペースを変えても平均は4〜5件/日で変わらない。
   変わるのは「復習の山の高さ」と「復習ゼロの日の数」だけ(3字/日でピーク12件、一括50字で翌日50件)
3. **コンテンツ枯渇が遅れる** — 3字/日でも全50字は17日で終わり、月額の1周期(30日)に満たない。
   上限が稼いでいたのは7日で、継続の仕組みにはなっていなかった

別の問題も抱えていた。**購読した当日は有料の中身に届かない**(その日の3字を使い切っていると、
課金しても第2章が翌日まで出ない)。審査メモでの説明だけで通したもので、
`docs/log/2026-09.md` に未回収の借りとして残っていた。

一方で、上限を外すと失われるものが1つある。このアプリの核である
「何日か後に、覚えた字が別の語で読みを変えて戻ってくる」**時間差**
(要件定義書 4.1-5 の第2段階、`docs/content-decisions.md` 5章)。
一気に進める人には「何日か後」が「十数分後」になる。
3字上限の下でも完全には守れていなかった。第2段階専用の回は枠を使わないので、
国(#54)→ 外国(#55)は同じ日に続けて出ていた。

## 決定

1. **1日3字は目標にする。** 達成したら祝い、漢字の樹への導線を主役にする。
   続けたい人は `Learn 3 more kanji` で3字ずつ開ける。回数に上限は無い(未購読なら第1章の範囲内)
2. **表示上の目標は3のまま動かさない。** 追加しても「6 of 6」にはせず、
   「目標達成済み + 今日の字数」で見せる。翌日の目標も3字で、前日の追加分は差し引かない
3. **第2段階の回は、読みが変わる字をすべて前日以前に学び終えているときだけ出す。**
   満たさない回に当たったら、**その手前でその日は止め**、「◯が明日、新しい語で戻ってくる」と添える
4. 上の規則で、目標3字に届く前に止まる日がある(3字/日のペースだと16日目だけ、#53・#54 の2字で止まる)。
   その日は `2 of 3` をそのまま出し、翌日に戻る字を添える。ストリーク(連続記録)も計測も無いので、未達に罰は無い
5. 「もう3字」を押した状態はその日だけの UI 状態にし、永続化しない。
   今日学んだ字数から開いた枠を導出するので、1字でも学べばアプリを落としても枠は戻る

## 理由

- 行き止まりが無くなり、初日の意欲に応えられる。購読した当日に有料の中身に届く
- 止まる場所が内容から決まる(「この字は一晩置いてから読みが変わる」)ので、数字の上限にならない。
  それでも結果として一気読みは分散する(最短5日: D1 #1〜#16 / D2 #17〜#29 / D3 #30〜#44 / D4 #45〜#54 / D5 #55〜#58)。
  1日の新出は最大16字で、翌日の復習の山も最大16件に収まる
- 会話文の順番は崩れない(止めるだけで、飛ばさない)
- 3字/日の人には、D16 の1日を除いて今までと同じ並びになる。完走も同じ17日
- `docs/content-decisions.md` 5章の「第2段階が同章内にある」懸念が、最低でも1日空く形で緩和される

## 却下した選択肢

- **上限3字のまま**: 今回のフィードバックがそのまま残る
- **ユーザーが目標字数を選ぶ(3 / 5 / 10)**: 変更する手段(設定画面)がアプリに無く、選び間違えた人が詰む。
  要件定義書 5.5「設定項目を増やさない」とも合わない
- **「もう3字」を1日1回(合計6字)に限る**: 行き止まりが6字目に移るだけで、6にする根拠が無い
- **翌日規則で出せない回を保留し、後ろの回へ進む**: 会話文の順番が入れ替わり、一気読みも分散しない
- **目標に届く前に止まった日を達成扱いにする**: 2字しか学んでいないのに「達成」と表示するのは嘘になる
- **その日だけ保留方式に切り替える**: 規則が2つになり、テストも説明も倍になる
- **無料枠では「もう」を出さない**(ADR-0003 の理由3を無料ユーザーにだけ残す): 合意した仕様に反する
- **押した状態を `user_settings` に永続化する**: マイグレーションが要り、その日だけの状態を将来の同期対象に入れる意味が無い

## 結果として受け入れるトレードオフ

- **ADR-0003 の理由3「習慣が付いてから課金判断」を捨てる。** 無料の第1章10字は、最短で初日に読み切れる(3+3+3+1)
- **ADR-0008 の前提「無料体験は実質約4日」が「最短1日」に変わる。** ADR-0008 の決定(境界は第1章のまま)は動かさない。
  転換が早まる方向にも、習慣が付く前に課金画面に当たる方向にも働きうる
- **計測手段が無い**(絶対規則9、要件定義書 7章「RevenueCat 内蔵の計測のみ」)。
  「購読者が数日で読み切り、低評価や返金につながる」懸念は、RevenueCat の返金と初回期間内の解約、
  App Store Connect の評価で見るしかない。翌日規則による最短5日が唯一の歯止め
- 一気読みでは、翌日の復習が最大16件になる(3字/日のピークは12件)
- 端末の時計を巻き戻すと翌日規則を回避できる(既存の方針どおり検出しない)
