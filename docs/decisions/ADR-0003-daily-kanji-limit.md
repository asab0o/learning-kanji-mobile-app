# ADR-0003: 1日の学習量上限を5字から3字に下げる

日付: 2026-08-15
ステータス: 採用

## 背景

要件定義書 5.1 の Must have #8 は「1日5漢字程度」と定めていた。理由として
書かれていたのは「復習の雪崩による離脱を防ぐ＆継続の仕掛け」だけで、
**なぜ5なのかの根拠は残っていない**。会話文集の決定事項も「1日5字ペースに合わせる」と
参照しているだけで、5そのものを検証してはいなかった。

最初に置かれた数字がそのまま通っている状態だったため、改めて検討した。

## 決定

**1日の学習量上限を3字にする。**

## 理由

### 1. このアプリは1字あたりが重い

WaniKani の lesson は記憶術カード1枚だが、このアプリの1字には
**会話文1本(1〜2往復)＋象徴イラスト＋種明かし**が付く。
5字なら会話文を5本読むセッションになる。同じ「5」でも中身の量が違う。

### 2. 当初の理由と噛み合っていなかった

「復習の雪崩を防ぐ」ために上限を設けたのに、SRS の復習量は新規投入量に
ほぼ比例する。5→3 にすれば復習の山も約0.6倍になる。
5字のままでは、上限を設けた理由を上限自身が薄めていた。

### 3. コンテンツ枯渇が遅れる

| ペース     | 全50字の完走 | 第1章(無料10字) |
| ---------- | ------------ | --------------- |
| 5字/日     | 10日         | 2日             |
| **3字/日** | **約17日**   | **約3〜4日**    |

MVP は50字しかない。10日で完走してサブスクを継続する理由が消えるより、
17日のほうがよい。無料範囲が3〜4日に伸びることで、**習慣が付いてから
課金判断が来る**導線になる。

### 4. 第2段階の間隔がわずかに緩和される

`docs/content-decisions.md` 5章の未解決点(第2段階が同章内に4回ある件)について、
#43生 → #48学生 の5文差は 5字/日 ならほぼ同じ日だが、3字/日 なら約2日空く。
解決はしないが悪化方向ではない。

## 変更のコスト

**コンテンツ側には一切埋まっていない。**

- 章構成(10/15/16/17文)は1日何字かに依存していない
- 第2段階8回の配置も依存していない
- `docs/会話文集.md` の原稿は1文字も変わらない

実装上も定数1つ。要件定義書 9章が SRS の間隔テーブルを
「定数配列のため後から調整可能」と扱っているのと同じ位置づけとする。
**SRS を実装するときは名前付き定数にし、マジックナンバーを散らさないこと。**

## 却下した選択肢

- **5字のまま維持**: 根拠が無く、上限を設けた理由と噛み合っていない
- **ユーザーが選べる設定にする**: MVP のスコープを増やす。
  要件定義書 5.5 の方針(設定項目を増やさない)に反する

## 結果として受け入れるトレードオフ

**TestFlight のテスターが完走するまで実時間で約17日かかる。**

iOS には Google Play のような「12人×14日」といった期間要件は無いため
審査上の問題は起きないが、9月上旬の機能凍結を目安にすると余裕が減る。
「最後まで通した感想」を早く得たい場合に効いてくる。

対策として、**テスト時に上限を外すデバッグ設定を用意する**(実装は数行、
審査には影響しない)。これは SRS 実装時の作業項目とする。
