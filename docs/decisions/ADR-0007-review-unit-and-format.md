# ADR-0007: 復習の単位は漢字1字とし、出題は意味の4択のみにする

日付: 2026-09-02
ステータス: 採用

## 背景

要件定義書の2箇所が矛盾していた。

- **4.1-4**「**文＋漢字のセット**をSRS(間隔反復)で復習」
- **5.1-4**「SRS復習 — 固定ステージ制(WaniKani式)。**出題は意味の選択式クイズのみ**」

前者を読むと復習中に会話文が再表示されることになり、後者を読むと4択だけが出る。
`docs/log/2026-08.md`(2026-08-28)で 5.1 を正とする判断は一度されているが、
**要件本文が直っていない**ため、SRS を実装するたびに同じ議論が起きていた。

`docs/plans/srs-lessons.md` はこの決着を次プランに送っており、
`docs/plans/srs-reviews.md` で閉じることになった。

## 決定

1. **スケジューリングの単位は漢字1字。** 会話文ではない
2. **出題は意味の4択のみ。復習中に会話文を再表示しない**(5.1-4 が正)
3. 「どの文で出会った字か」は `lesson_events`(`kanji_id` と `sentence_id` のペア)が持つ。
   **`review_events` からは `sentence_id` を削除する**
4. 要件 4.1-4 の文言を、この決定に合わせて差し替える

## 理由

- **1つの漢字が複数の文に出る。** 段階的再登場(4.1-5)が差別化の核なので、
  同じ字が第1段階・第2段階と別の回に現れる。「文＋漢字のセット」を単位にすると、
  同じ字のスケジュールが文の数だけ分裂し、**ステージがどれを指すのか決まらなくなる**
- **復習で会話文を出すと、答えが本文に書いてある。** 意味を問う4択の下に、
  その字を含む文とふりがなと英訳が並ぶ。推測が成立しない
- **1問あたりの時間が伸びる。** 1日18件前後を数分で終える設計(ADR-0003 の
  「復習の雪崩による離脱を防ぐ」)と噛み合わない
- **`review_events.sentence_id` に入れるべき値が無くなる。** 導入回の ID を入れる案も
  検討したが、それは `lesson_events` から常に引ける導出値で、復習イベントごとに
  同じ値をコピーすることになる。**まだ配っていない今なら列を消すのが最も安い**

## 却下した選択肢

- **4.1 を正とし、復習で会話文を再表示する。** 上記のとおり答えが見えてしまう
- **折衷案: 答え合わせのときだけ導入回の会話文を出す。**
  `ConversationView` は画面まるごとの構成で復習カードに収まらず、ふりがな描画を
  復習側に持ち込むと差分が一気に膨らむ。**v2 の候補として送る** —
  外部テストで「文の中で見たい」という声が出たら、答え合わせの下に
  導入回への導線を1本足すのが最小の対応になる
- **`review_events.sentence_id` を nullable にする。** SQLite の NOT NULL 制約の変更は
  テーブル再作成になる。どうせ作り直すなら、導出値の列は消したほうがよい

## 結果として受け入れるトレードオフ

- **要件4.1-4 の素朴な読み(「文＋漢字のセット」)は失われる。** 文と字の対応は
  `lesson_events` に残るが、**復習の体験としては字が単独で出てくる**
- **復習画面に会話文への導線が無い。** 「この字、どの場面で出てきたっけ」と思っても
  復習中には辿れない。漢字の樹(4.5)が入れば別経路で辿れるようになる
- **`review_events` の1行から「どの文の復習か」は読めなくなる。**
  `kanji_id` で `lesson_events` を引く必要がある
