# ADR-0001: 開発ハーネスの構成

日付: 2026-08-09
ステータス: 採用

## 背景

個人開発 + AIエージェントで、約2ヶ月でリリースまで到達する必要がある。
レビューしてくれる同僚がいないため、品質のガードレールを人間の注意力ではなく
仕組みに置く必要がある。

## 決定

4層で構成する。

1. **コンテキスト層** — ルート `CLAUDE.md` を80行以内に保ち、詳細は `docs/` に置いて
   必要なときだけ読ませる。`src/db/` と `src/content/` にはディレクトリ別 `CLAUDE.md` を置く
2. **承認層** — `permissions.defaultMode: "plan"` により、承認なしでは書き込めない
3. **検証層** — `pnpm run check`(型 + lint + テスト + コンテンツ検証)を単一の合格基準にする
4. **ループ層** — `Stop` フックが `check` を自動実行し、失敗したら停止をブロックして
   エラーを返す。最大3周で打ち切る

## 理由

- **CLAUDE.md を短く保つ**: 常時ロードされるため、長いほど他の情報を圧迫し、
  かつ長文の規約ほど守られなくなる。「必ず効かせたい規約」だけを常時ロードに置く
- **プランモードをデフォルトにする**: 「プランを立ててから実装する」を指示ではなく
  権限で強制する。指示は無視されうるが権限は無視できない
- **コンテンツ検証をテストと同格にする**: このアプリは会話文58文の学習順序が
  データの整合性そのもの。「第3章に未習漢字が混入している」は目視では検出できないが、
  機械なら確実に見つかる。型チェックやlintと同じ扱いで毎回回す価値がある
- **サブエージェントを分ける**: 設計時の調査ログとレビュー時の差分読解をメインの
  会話に持ち込まないため。加えて、実装したのと別のコンテキストでレビューさせることで、
  自分の書いたコードを無批判に肯定しにくくする

## 却下した選択肢

- **CLAUDE.md に全部書く**: コンテキストを常時圧迫し、規約が守られにくくなる
- **CI(GitHub Actions)でチェックする**: 個人開発では push 前に結果が欲しい。
  ローカルの Stop フックの方がループが速い。将来 CI を足すのは妨げない
- **pre-commit フック**: コミット時では遅い。Claude が「完了」と言う瞬間に
  検証したいので Stop フックを選んだ
- **自己修正ループを無制限にする**: 直せないエラーで延々トークンを消費する。
  3周で打ち切り、残りを人間に報告させる

## 結果として受け入れるトレードオフ

- Stop フックにより、コード変更があったターンの終了が数十秒遅くなる
- プランモードがデフォルトなので、些細な修正でも一度承認が要る。
  急ぐときはセッション中にモードを切り替えて回避する
