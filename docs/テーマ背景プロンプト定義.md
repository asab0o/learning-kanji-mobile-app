# テーマ背景装飾 画風プロンプト定義

最終更新: 2026-08-21
用途: テーマごとの全画面背景装飾(桜のみ確定・生成画像1枚 + ベクター装飾)

漢字イラストとは**用途が別物**(主役ではなく地)なので、パレットも合格ラインも別に持つ。
漢字イラスト側は `docs/画風プロンプト定義.md` を参照。

---

## 1. 確定した方向性

**担当を分けるハイブリッド。**生成AI画像は質感(グラデーション＋紙の粒感)だけを担い、
花びら・落下の軌跡は `react-native-svg` でコード側に描く(`src/theme/motifs/sakura-petals.tsx`)。
経緯は ADR-0004(2026-08-21 追記)を参照。

| 項目       | 決定                                                                  |
| ---------- | ---------------------------------------------------------------------- |
| 対象       | 桜テーマのみ。ノーマル / 東京の夜景はデザイン未確定のため保留          |
| 出典       | デザイン案「春 ／ 春泥棒」(ADR-0004)。質感の方向性は Claude Design で追加生成 |
| AI画像の担当 | グラデーション＋紙の粒感**のみ**。桜のモチーフ(花びら・軌跡)は含めない |
| モチーフの担当 | 花びら・軌跡は `react-native-svg`。色は `theme.accent` を直接参照      |
| 枚数       | 生成画像1枚。全画面で使い回す(要件5.3)                                 |
| サイズ     | 縦長 9:19.5(1179×2556 相当)。フルブリード                              |
| 配置先     | `assets/themes/sakura/backdrop.png`                                    |

漢字イラスト側から**2つの原則を引き継ぐ**。

- **純黒 `#000000` を使わない。** 最も濃い色でも charcoal 止まり
- **文字・漢字を明示的に排除する。** 生成AIは崩れた日本語文字を高頻度で描き込む

## 2. なぜ花びら・軌跡をAI画像から外したか

当初は花びらと軌跡も含めて1枚で生成する想定で、HEXコード・角度・不透明度まで
指定した詳細なプロンプトを書いた。Midjourneyで3回試したところ、毎回意図と違う
結果になった。

- **「trailing a streak behind it(軌跡を引きずる)」という表現が、風船の紐のように
  直訳された。** 花びらの丸と、そこから伸びる曲線1本ずつのペアになり、
  「落下の軌跡」ではなく「紐で吊るされた風船」に見える絵が2回とも再現した
- **「the moment after the blossoms have already fallen(花びらが落ちきった後)」
  という一文が、花びら自体を省く指示のように読まれた。** 「落ちきった後」は
  文字通りには「もう花びらは無い」情景なので、花びらを求める別の段落と
  矛盾していた
- **HEXコードは近似にしかならない。** `#D2839C` を指定しても赤み寄りのオレンジに
  ズレる。生成のたびに色を微調整しても収束しない

言葉を削って短くした版(角度・不透明度・HEXを外し、「trailing」を
「long exposure(長秒露光)のブレ」という写真的な比喩に置き換えた版)でも
改善しなかった。

一方、Claude Design に **「Yorushikaの春泥棒をイメージしたデザイン」という
短く曖昧な指示**だけで作らせた、空色〜暖色のグラデーション＋紙の粒感の絵は
狙い通りの質感で評判が良かった(花びら・軌跡のモチーフは含まれていない)。

**教訓: 生成AIには質感のような「言葉にしにくいがモデルが得意なもの」を任せ、
色や配置のように正確さが要るものはコードで描く。** 詳細な指示を積むほど、
モデルは字面を律儀に(でも見当違いに)拾ってしまう。

## 3. AI画像側のベースプロンプト(質感のみ)

```
A quiet Japanese watercolor sky: pale dusty blue fading into warm cream,
textured like fine washi paper. Extremely low contrast, no focal point,
large empty areas below the sky wash. Muted, faded, restrained.

--ar 6:13
--no text, letters, japanese characters, kanji, watermark, cherry blossoms,
flowers, petals, tree, high saturation, strong contrast, vignette, dark
corners, borders, frames, centered subject, photorealistic, 3d render,
drop shadows, neon, pure black
```

### 補足

- **`--no` に `cherry blossoms, flowers, petals, tree` を含める。** 桜のモチーフは
  コード側(SVG)で描くため、AI画像に混ざると二重になったり色が食い違ったりする
- **`--ar` は整数比のみ。** Midjourneyは `9:19.5` のような小数を受け付けない。
  縦長 9:19.5 と同じ比率の整数比は `6:13`(9:19.5 を3で割ると6:13)
- HEXコード・角度・不透明度のような数値指定は**入れない**。上記「なぜ外したか」の通り、
  精緻な指示は誤読を招く。曖昧な言葉に任せたほうが結果が安定した
- Midjourney以外(DALL-E / Imagen 等)を使う場合、`--ar` は出力サイズ指定に置き換え、
  `--no` 以降は「Do not include: ...」の自然文にする
- Claude Design で「Yorushikaの春泥棒をイメージしたデザイン」のような曲名参照だけで
  生成する方法でもよい。むしろその方が評判が良かった

## 4. モチーフ側(花びら・軌跡)の仕様

実装は `src/theme/motifs/sakura-petals.tsx`。`react-native-svg` の `Ellipse` + `Line`。

| 項目 | 値 |
|---|---|
| 花びらの数 | 5〜6枚 |
| 配置 | 左右の端寄りに散らす。中央(会話文・漢字イラストが載る領域)は空ける |
| 軌跡の傾き | 20度前後(垂直から) |
| 色 | `theme.accent` をそのまま参照。ハードコードしない |
| 不透明度 | 花びら本体 > 軌跡(軌跡を薄くする) |

色をコードで直接トークンから引くため、**AI画像のようなHEXのズレは原理的に起きない**。
座標を変えたいときはコンポーネント内の `PETALS` 配列を編集する。

## 5. カラーパレット(AI画像専用)

| 役割                       | 色                 | HEX       |
| -------------------------- | ------------------ | --------- |
| 地                         | warm off-white     | `#FBF4F4` |
| 上部の空                   | soft dusty blue    | `#C5D6E8` |
| 最暗色(使うとしても極薄)   | charcoal           | `#453B41` |

花びら・軌跡の色(`muted dusty rose` `#D2839C`)はコード側のトークンなので、
このパレットには含めない。`#FBF4F4` は `src/theme/themes/sakura.ts` の `background` と
同じ値。**背景画像とトークンで色がずれると画面が濁る**ので、片方を変えたらもう片方も直す。

## 6. 合格ライン(生成しただけで採用しない)

生成物は必ずシミュレータに、SVGモチーフを重ねた状態で確認する。1〜2で落ちたらやり直す。

1. **本文が読めるか** — `#453B41` の明朝 17.5pt を、背景の一番濃い箇所の上で読めること。
   **これが本当の合格ライン**
2. **白い吹き出しが浮くか** — `#FFFFFF` の吹き出しと `#FBF4F4` の地が判別できること。
   差が小さいので潰れやすい
3. **SVGの花びらが背景に馴染むか** — 生成画像の色調と `theme.accent` の彩度がかけ離れて
   浮いていないこと。かけ離れていたら AI画像側のプロンプトの寒色/暖色バランスを調整する
4. **中央が空いているか** — 漢字イラストが載る画面中央に模様が来ていないこと
5. **どの画面でも破綻しないか** — 全画面固定で1枚を敷くため、会話・樹・設定のどれで見ても成立すること

## 7. 制作フロー

1. 上記プロンプトで3〜4枚生成し、並べて**一番「静か」なもの**を選ぶ
2. `assets/themes/sakura/backdrop.png` として配置する
3. `src/theme/themes/sakura.ts` の `backdrop` を差し替える

   ```ts
   backdrop: { source: require('@/assets/themes/sakura/backdrop.png'), opacity: 1 },
   ```

   **Metro は `@/assets/*` をそのまま解決できる**(確認済み)。一方 **Jest は落ちる**ので、
   `package.json` の `jest.moduleNameMapper` に `^@/assets/(.*)$` を
   `^@/(.*)$` より**先に**書いてある(順序が逆だと `src/assets/` を探しにいく)。
   同種のエイリアスを足すときは同じ罠に注意する

4. `motif: 'sakuraPetals'` は既にコード側で有効化済みなので、画像を差し替えるだけで
   両方のレイヤーが揃う
5. 合格ライン5項目をシミュレータで確認する
6. 濃すぎる場合は**生成をやり直す前にまず `opacity` を下げる**。
   要件5.3 の「背景装飾は薄く敷く」はここで効かせる。

   **現在の採用値は `opacity: 0.35`。** `1` のままだと生成画像のクリーム色が
   地の `#FBF4F4` を完全に覆い、本文コントラストが 6.77:1 まで落ちる(AAA基準の7:1未満)。
   `0.35` に下げると 8.73:1 まで回復し、下地のピンク寄りの白も透ける。
   **生成画像の色みがトークンと違っても、`opacity` で混ぜれば中間に寄せられる**ので、
   色みのズレだけを理由に再生成しなくてよい
