# テーマ背景装飾 画風プロンプト定義

最終更新: 2026-08-22
用途: テーマごとの全画面背景装飾(桜のみ確定・生成画像1枚)

漢字イラストとは**用途が別物**(主役ではなく地)なので、パレットも合格ラインも別に持つ。
漢字イラスト側は `docs/画風プロンプト定義.md` を参照。

---

## 1. 確定した方向性

**生成画像1枚にすべてを含める。**空のグラデーション・紙の粒感に加えて、
花びらと落下の軌跡もこの1枚が担う。コード側で描き足すものは無い。

一時期は花びら・軌跡だけを `react-native-svg` に切り出すハイブリッドにしていたが、
すべて含んだ画像が意図通りに生成できたため撤回した(ADR-0004 の 4b)。

| 項目   | 決定                                                          |
| ------ | -------------------------------------------------------------- |
| 対象   | 桜テーマのみ。ノーマル / 東京の夜景はデザイン未確定のため保留  |
| 出典   | デザイン案「春 ／ 春泥棒」(ADR-0004)。実制作は Claude Design   |
| 内容   | 空のグラデーション＋紙の粒感＋花びら＋落下の軌跡               |
| 枚数   | 1枚。全画面で使い回す(要件5.3)                                 |
| サイズ | 縦長 9:19.5 相当。現物は 852×1846                              |
| 配置先 | `assets/themes/sakura/backdrop.png`                            |
| 不透明度 | `1`(理由は §7)                                               |

漢字イラスト側から**2つの原則を引き継ぐ**。

- **純黒 `#000000` を使わない。** 最も濃い色でも charcoal 止まり
- **文字・漢字を明示的に排除する。** 生成AIは崩れた日本語文字を高頻度で描き込む

## 2. 何が効かなかったか(生成の記録)

**この節が一番の資産。**別テーマの背景を作るときに同じ失敗を繰り返さないための記録。

最初は花びらと軌跡も含めて1枚で生成する想定で、HEXコード・角度・不透明度まで
指定した詳細なプロンプトを書いた。Midjourneyで3回試したところ、毎回意図と違う
結果になった。

- **「trailing a streak behind it(軌跡を引きずる)」という表現が、風船の紐のように
  直訳された。** 花びらの丸と、そこから伸びる曲線1本ずつのペアになり、
  「落下の軌跡」ではなく「紐で吊るされた風船」に見える絵が2回とも再現した
- **「the moment after the blossoms have already fallen(花びらが落ちきった後)」
  という一文が、花びら自体を省く指示のように読まれた。** 「落ちきった後」は
  文字通りには「もう花びらは無い」情景なので、花びらを求める別の段落と
  矛盾していた
- **HEXコードは近似にしかならない。** `#D2839C` を指定しても赤み寄りのオレンジに
  ズレる。生成のたびに色を微調整しても収束しない

言葉を削って短くした版(角度・不透明度・HEXを外し、「trailing」を
「long exposure(長秒露光)のブレ」という写真的な比喩に置き換えた版)でも
改善しなかった。

「long exposure(長秒露光)のブレ」という写真的な比喩に置き換えた版)でも
改善しなかった。

一時は花びら・軌跡だけを `react-native-svg` に切り出すハイブリッドにしたが、
**自前のSVGでも同じ失敗を再現した**。均一な太さの直線を花びらから伸ばしたところ、
まさに「風船の紐」に見えた(グラデーションでフェードさせて解決)。
つまりこれは生成AI固有の問題ではなく、**「軌跡」という表現の落とし穴**だった。

## 3. 何が効いたか

**Claude Design に「Yorushikaの春泥棒をイメージしたデザインを作れますか」と
聞いただけ。** 構図も色も枚数も指定していない。これで空のグラデーション・紙の粒感・
花びら・落下の軌跡がすべて揃った、現在採用している画像が出た。

**教訓: 生成AIには短く曖昧に指示する。** 詳細な数値や比喩を積むほど、モデルは
字面を律儀に(でも見当違いに)拾う。作りたいものに名前や参照(曲名・作品名)が
あるなら、それを渡すのが一番早い。

別テーマ(ノーマル / 東京の夜景)を作るときも、まずこの方法を試すこと。
細かいプロンプトを書くのは、それで出なかったときの次善策とする。

### 守るべき制約(短い指示に付け足す最小限)

- **文字・漢字を排除する。** 生成AIは崩れた日本語文字を高頻度で描き込む
- **純黒 `#000000` を使わない。** 最も濃い色でも charcoal 止まり(画風プロンプト定義 §3)
- **中央を空ける。** 会話文と漢字イラストが載るため
- **`--ar` は整数比のみ**(Midjourneyの場合)。縦長 9:19.5 と同じ比率の整数比は `6:13`

## 4. カラーパレット

| 役割                       | 色                 | HEX       |
| -------------------------- | ------------------ | --------- |
| 地                         | warm off-white     | `#FBF4F4` |
| 上部の空                   | soft dusty blue    | `#C5D6E8` |
| 花びら・落下の軌跡         | muted dusty rose   | `#D2839C` |
| 最暗色(使うとしても極薄)   | charcoal           | `#453B41` |

`#FBF4F4` と `#D2839C` は `src/theme/themes/sakura.ts` の `background` / `accent` と
同じ値。**背景画像とトークンで色がずれると画面が濁る**ので、片方を変えたらもう片方も直す。

ただし生成AIはHEXコードどおりの色を出さない(§2)。多少ズレても、
`opacity` を下げて下地のテーマ色と混ぜれば中間に寄せられるので、
色みのズレだけを理由に再生成しなくてよい。

## 5. 合格ライン(生成しただけで採用しない)

生成物は必ずシミュレータで確認する。1〜2で落ちたらやり直す。

1. **本文が読めるか** — `#453B41` の明朝 17.5pt を、背景の一番濃い箇所の上で読めること。
   **これが本当の合格ライン。**コントラスト比 7:1(AAA)以上を目安にする
2. **白い吹き出しが浮くか** — `#FFFFFF` の吹き出しと地が判別できること。
   差が小さいので潰れやすい
3. **花びらが見えるか** — `opacity` を下げると軌跡から先に消える。軌跡が残っているか
4. **中央が空いているか** — 漢字イラストが載る画面中央に模様が来ていないこと
5. **どの画面でも破綻しないか** — 全画面固定で1枚を敷くため、会話・樹・設定のどれで見ても成立すること

## 6. 制作フロー

1. §3 の方法で生成する(短く曖昧に、参照を渡す)。複数出たら**一番「静か」なもの**を選ぶ
2. `assets/themes/sakura/backdrop.png` として配置する
3. `src/theme/themes/sakura.ts` の `backdrop` を差し替える

   ```ts
   backdrop: { source: require('@/assets/themes/sakura/backdrop.png'), opacity: 1 },
   ```

   **Metro は `@/assets/*` をそのまま解決できる**(確認済み)。一方 **Jest は落ちる**ので、
   `package.json` の `jest.moduleNameMapper` に `^@/assets/(.*)$` を
   `^@/(.*)$` より**先に**書いてある(順序が逆だと `src/assets/` を探しにいく)。
   同種のエイリアスを足すときは同じ罠に注意する

4. 合格ライン5項目をシミュレータで確認する

## 7. 不透明度の決め方

**画像ごとに測り直す。固定値ではない。**

現在の採用値は **`opacity: 1`**。この画像は空が淡く、`1` のままでも空の一番濃い箇所での
本文コントラストが 7.41:1 で AAA 基準(7:1)を満たす。

**下げすぎると花びらが消える。** 直前まで採用していた `0.35` は、花びらをコード側(SVG)で
描いていた頃の値で、花びらを含むこの画像に適用すると花びらも軌跡もほぼ見えなくなった。

一方、より濃い画像では下げる必要がある。以前の版は `1` だと本文コントラストが
6.77:1 まで落ち、`0.35` にして 8.73:1 まで回復させた。

つまり**画像の濃さ次第で最適値が変わる**ので、差し替えたら必ず
「本文コントラスト 7:1 以上」と「花びらが見える」の両立点を実測で探すこと。
両立しない場合は本文の可読性を優先する(要件5.3 の視認性の注意が上位)。
