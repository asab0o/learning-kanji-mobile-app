# ドキュメントの歩き方

`docs/` 配下のすべてのドキュメントは **flow / stock / log** のいずれかに属する。
**書き換えてよいかどうかがそこで決まる。**

種別の書いてある場所は2通り。

- `docs/` 直下のファイル → **そのファイルの先頭1行**
- `decisions/` `plans/` `log/` のように**ディレクトリごと種別が決まっているもの**
  → 各ディレクトリの `README.md`。中の個別ファイルには書かない
- 例外は `requirements.md` だけ。1ファイルの中に flow と stock が同居しているので、
  **章ごとの注記**を見る

## 3分類

| 種別 | 何を書くか | 更新の仕方 |
|---|---|---|
| **flow** | なぜそう決めたか。決めた時点の判断 | **書き換えない。** 覆すときは新しいものを起こし、古い方に「置き換え済み」と印を付ける |
| **stock** | いまの状態。現在の仕様・現在の未決事項 | **都度上書きする。** 常に最新だけが書かれている状態を保つ |
| **log** | いつ何をやったか。誰(人 / AI)がやったか | **末尾に追記するだけ。** 過去のエントリを書き換えない |

これは絶対規則5(SRSの状態は `review_events` への追記のみ、現在状態はそこから導出する)と
同じ形をしている。**flow と log が追記のみのイベント、stock がそこから導出された現在状態のキャッシュ。**
迷ったら「これは事実の記録か、それとも現在値か」で分ける。

## いま何がどこにあるか

### flow — 書き換えない

| ファイル | 中身 |
|---|---|
| `decisions/ADR-*.md` | 設計・要件の意思決定とその理由 |
| `content-decisions.md` | 会話文の方針を決めた理由。**会話文の最終権威** |
| `plans/*.md` | 承認済みの実装プラン。実装中だけ stock として更新し、完了したら凍結する |
| `requirements.md` の 1〜3章 / 10章 | このアプリを作る理由と、調査した時点の競合状況 |

### stock — 都度更新する

| ファイル | 中身 |
|---|---|
| `requirements.md` の 4〜9章 | 現在の仕様と、現在の未決事項。**要件の最終権威** |
| `architecture.md` | 現在のレイヤ構成と配置ルール |
| `data-model.md` | 現在のDBスキーマ方針 |
| `content-spec.md` | `src/content/` の現在の契約 |
| `会話文集.md` | 会話文の実データの正 |
| `対象漢字リスト.md` | 対象漢字の実データの正 |
| `release-checklist.md` | **リリースまでに残っていることの現在値** |
| `画風プロンプト定義.md` | 漢字イラストの現在のプロンプト |
| `テーマ背景プロンプト定義.md` | テーマ背景の現在のプロンプト |

### log — 追記のみ

| ファイル | 中身 |
|---|---|
| `log/YYYY-MM.md` | 月ごとの作業録。人がやったこと / AIに任せたこと / やり直したこと |

## 新しいドキュメントをどこに置くか

1. **「なぜ」を書きたい** → flow。設計・要件の判断なら `decisions/` に ADR を起こす
2. **「いまどうなっているか」を書きたい** → stock。既存の stock ドキュメントに追記できないか先に見る。
   新規ファイルを増やすより、既存を更新するほうが正しいことが多い
3. **「何をやったか」を書きたい** → log。`/log` で追記する
4. どれでもない、その場限りのメモ → **`docs/` に置かない**

`docs/` 直下に新規ファイルを足すときは、**先頭に種別の1行を入れ、この README の表に足す**。
`decisions/` `plans/` `log/` の中に足すときは、種別はディレクトリで決まっているので何も書かない。

## 1つの出来事が複数に散るのは正常

例: 桜テーマの配色を決めたとき

| 何 | どこ |
|---|---|
| 「テーマ3種のカラーコード」が未決だという事実 | `requirements.md` 9章(stock。決まったらチェックを付ける) |
| デザイン16案から「春泥棒」を選んだ理由 | `decisions/ADR-0004`(flow。凍結) |
| 決まった結果としての実際の色 | `src/theme/` と `requirements.md` 5.3(stock) |
| その週に実装して背景を作り直したこと | `log/2026-08.md`(log。追記) |

**理由を stock に書かない。現在値を flow に書かない。** これを守れば、
「この記述は古いのか、それとも当時の記録なのか」で悩まなくなる。
