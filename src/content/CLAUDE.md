# src/content/ の規約

このアプリの中核資産。ここが壊れると学習体験そのものが成立しない。
**編集する前に `docs/content-decisions.md`(方針の根拠)と `docs/content-spec.md`(契約)を読むこと。**

## 触る前に

- 追加・変更は `/add-content` スキルの手順で行う
- 実データの原稿は `docs/会話文集.md`(v0.2)
- データを書いたら必ず `pnpm run validate:content` を通す
- **AIはこのデータの承認者ではない。** 日本語の最終品質判断は開発者本人が行う

## 未習漢字は使ってよい

**既習漢字だけで縛らない。** ふりがな＋英訳があるので読める。
既習だけで書くと不自然な文しか作れず、「日本語に触れている」実感が失われる。
対象50字の外の字(星・旅・今)も、あとで習う字を先に出すことも許容されている。

未習を避けるのは次の2箇所だけ。

1. 第2段階の演出をする漢字の周辺
2. 推測クイズの出題

検証スクリプトは未習漢字をエラーにしない。章別の密度を集計して出すだけ。
**第1章の密度だけは意識する**(無料範囲で離脱が最も起きる場所のため)。

## 絶対に守ること

1. **第2段階の対象字は、その回より前に導入済みであること。**
   訓読みを知らない字の読みが変わっても、学習者には何も起きない
2. **第2段階は `kanjiIds` が配列。** 時間=時＋間、大学=大＋学、外国=外＋国 のように
   1語で2字の読みが同時に変わる回が8回中3回ある。片方だけ記録しない
3. **訓読みを先、音読みを後。** 例外字(天・本・語)は `readingIntroduction: 'on-only'` とし、
   訓読みをデータに登録しない。第2段階の対象にもしない
4. **1文につき新出漢字は最大1字。** `newKanjiId: null` が許されるのは
   `reencounters` を持つ第2段階専用の特別回だけ
5. **`isFree` は第1章の文だけ `true`。** 課金境界と章の切れ目を一致させる
6. **空(猫)は挨拶・応答をしない。** 要求・状態・存在のみ。単語だけの雑な話し方。
   空が出る回はミアとのやりとりを1往復以上入れる(受け身のオチ要員にしない)
7. **ミアは空に対してだけタメ口。** 対おばあちゃんは丁寧語。
   タメ口の回は短く易しい文になるので、丁寧語に書き直さない
8. ふりがな・英訳を全行に付ける。ローマ字はヘボン式(生成方法は未確定)
9. `id` は ULID

## `validate.ts` を触るとき

**チェックを通すためにルールを緩めることは禁止。**
ルールが誤っていると考えるなら、先に `docs/content-decisions.md` を直し、
なぜ変えるのかを `docs/decisions/` に残してから変更する。

新しいルールを足すときは、必ず `validate.test.ts` にフィクスチャベースのテストを添える。
実データに依存したテストを書かない(データが増えるたびに壊れるため)。

## 学習順を入れ替えるとき

`order` を1つ変えると、第2段階の対象字が未習になって演出が空振りする可能性がある。
**先に影響範囲を見積もってから作業する。**
未習漢字そのものは許容されているので、壊れるのは第2段階の配置だけ。
